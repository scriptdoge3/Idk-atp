# Project notes

This repo is the **Half-Life 2 mobile port**: a from-scratch engine that runs
on the user's own Source-format game files, targeting the Pixel 11 Pro
(Android, arm64, Vulkan). The plan and roadmap live in `README.md`; work
through the roadmap in order unless told otherwise.

## Clean-room rules (from README, non-negotiable)

- Never read, fetch or copy Valve engine code, leaked code, or Source SDK code
  (including `bspfile.h`-style headers mirrored on GitHub). File formats come
  from public documentation (Valve Developer Community wiki); game behavior
  from observing the real game.
- No game assets in the repo. Tests use synthetic data generated by
  `tests/make_test_*.py`.

## Build and test

```sh
sh tests/run.sh          # desktop build + every synthetic-data test
```

Plain C++17, no dependencies, `-Wall -Wextra -Wpedantic` must stay clean.
Decode file formats field by field with the explicit little-endian helpers;
never cast raw bytes to structs.

## Android builds in this cloud container

The container has Gradle and a JDK but **no Android SDK or NDK**, and
containers are reclaimed, so install per session (~3 min, run it in the
background):

```sh
mkdir -p /opt/android-sdk/cmdline-tools
curl -sSL -o /tmp/cmdtools.zip \
  https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip -q -o /tmp/cmdtools.zip -d /opt/android-sdk/cmdline-tools
mv /opt/android-sdk/cmdline-tools/cmdline-tools /opt/android-sdk/cmdline-tools/latest
export ANDROID_HOME=/opt/android-sdk ANDROID_SDK_ROOT=/opt/android-sdk
yes | /opt/android-sdk/cmdline-tools/latest/bin/sdkmanager --licenses > /dev/null
/opt/android-sdk/cmdline-tools/latest/bin/sdkmanager --install "ndk;27.1.12297006"
# for an APK also: "platform-tools" "platforms;android-35" "build-tools;35.0.0"
```

Cross-compile the engine core and check it is really device code:

```sh
NDK=/opt/android-sdk/ndk/27.1.12297006   # spell the version out, see below
cmake -S . -B out-arm64 -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26
cmake --build out-arm64
$NDK/toolchains/llvm/prebuilt/linux-x86_64/bin/llvm-objdump -f out-arm64/libcore.a \
  | grep -m1 architecture   # -> aarch64
```

The toolchain defines `ANDROID`, so `CMakeLists.txt` skips the desktop tools
and tests there.

Gotchas:
- Pin the NDK path. The Android Gradle Plugin installs its own NDK next to
  yours, so a glob like `ndk/*` can match two dirs and break the toolchain path.
- `sdkmanager --licenses` hangs without `yes |`.
- For an APK: Gradle needs `local.properties` with `sdk.dir=/opt/android-sdk`;
  known-good versions are AGP 8.7.3, Kotlin 2.0.21, compileSdk 35, JDK 17;
  build with `gradle :app:assembleDebug --no-daemon`. AGP downloads its own
  CMake 3.22.1 on the first native build.
- No emulator (no KVM), so an APK can be built but not run here.
- A cross-compiled `.a` is not an APK. An APK also needs a Gradle project,
  manifest and activity, which is new code: ask the user before adding an
  Android app shell. They have objected to unrequested changes before.

## Network

The VDC wiki (developer.valvesoftware.com) sits behind a bot challenge and
web.archive.org is unreachable from the container, so format docs can't be
fetched here. Note any format detail that still needs checking against real
